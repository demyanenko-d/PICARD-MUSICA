# Формат банка `.ssb`

Банк — это `.sf2`, заранее превращённый на ПК в готовые трекерные
инструменты. Плата его **читает, а не разбирает**: все записи постоянного
размера и выровнены на 4 байта, ссылки — только индексы и смещения, строк
переменной длины нет. Чтение сводится к приведению указателя к структуре и
индексации.

Порядок байт — little-endian. Единственный источник истины —
`backend/core/bank/bank_format.h`: его включают и препроцессор, и прошивка,
и у каждой записи `static_assert` на размер, так что разойтись молча они не
могут.

## Раскладка файла

```
[ заголовок         96 Б  ]
[ presets     16512 × 4 Б ]  (банк, программа) -> список слоёв
[ layers          N × 4 Б ]  диапазон velocity + инструмент
[ instruments    N × 28 Б ]  готовый трекерный инструмент
[ envelopes     N × 108 Б ]  точки, время в миллисекундах
[ keymap          N × 4 Б ]  нота -> сэмпл
[ samples        N × 36 Б ]  дескриптор + смещение прогона в PCM
[ model            2048 Б ]  частоты модели сжатия
[ PCM                     ]  прогоны Raw8/Dpcm8, за каждым его контрольные точки
```

Порядок таблиц в файле задаётся смещениями из заголовка, а не этой
картинкой.

## Путь от ноты до сэмпла

Таблицы устроены под один запрос: «программа, нота, сила удара — что
играть». Он проходит их насквозь, без поиска.

```
lookup(bank_no, program, note, velocity) -> up to 4 samples

    preset = presets[bank_no * 128 + program]      # always present
    sel    = quantize(velocity)                    # to one of 6 bands

    if no layer of preset covers sel:
        sel = velocity                             # narrow band: exact value

    out = []
    for layer in preset.first_layer .. +preset.layer_count:
        if sel < layer.vel_lo or sel > layer.vel_hi: continue

        inst = instruments[layer.instrument]
        sample, note_offset = kNoSample, 0
        for r in keymap[inst.keymap_first .. +inst.keymap_count]:
            if r.start_note > note: break
            sample, note_offset = r.sample_index, r.note_offset

        if sample == kNoSample: continue           # layer misses this note
        out.append((sample, note_offset, inst))
        if len(out) == 4: break                    # kMaxNoteLayers

    return out
```

Три вещи в этом коде важнее остальных.

**Ответов бывает несколько.** Слои звучат одновременно, и каждый занимает
свой голос; потолок — четыре. По архиву в 126 тысяч `.mid` на сочетание
«нота + сила удара» приходится один слой в 50.7% случаев, два в 41.3%, три
в 7.2%, четыре в 0.7%.

**Сила удара округляется к шести полосам** `{39, 61, 75, 87, 100, 115}` —
квантилям velocity по той же библиотеке. Без этого файл с множеством
оттенков задевал бы тем больше разных слоёв, чем он выразительнее (в рояле
SGM их 1133 на 340 полос), и каждый тянул бы свои сэмплы в память. На
громкость округление не влияет: она считается по точному значению.

**Ударные — тот же путь.** Набор лежит в синтетическом банке 128, нота
выбирает инструмент через keymap, а фиксированную высоту выражает
`note_offset`. Отдельной ветки для перкуссии нет нигде.

Пустого ответа этот путь не даёт по построению: пресет есть на каждый из
16512 слотов, а если сэмпла на ноту нет ни у одного слоя, нота просто не
звучит.

## Заголовок

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 4 | `magic` — `'S','S','B','1'` (`0x31425353`) |
| 4 | 2 | `version` — сейчас **5** |
| 6 | 2 | `rate_cap_hz` — потолок частоты при сборке, справочно; 0 — родные частоты |
| 8 | 4 | `total_bytes` — весь блоб |
| 12 | 4 | `table_crc32` |
| 16 | 4 | `pcm_crc32` |
| 20 | 4 | `pcm_offset` — от начала блоба |
| 24 | 4 | `pcm_bytes` |
| 28 | 4 | `presets_offset` |
| 32 | 4 | `layers_offset` |
| 36 | 4 | `instruments_offset` |
| 40 | 4 | `envelopes_offset` |
| 44 | 4 | `keymap_offset` |
| 48 | 4 | `samples_offset` |
| 52 | 4 | `model_offset` |
| 56 | 2 | `layer_count` |
| 58 | 2 | `instrument_count` |
| 60 | 2 | `envelope_count` |
| 62 | 2 | `sample_count` |
| 64 | 4 | `keymap_count` |
| 68 | 28 | `name` — из `INFO/INAM` исходного `.sf2`, для журнала |

Сигнатура одна у всех версий, версия — отдельным полем: так банк старой
версии в журнале отличается от битого файла. Банк чужой версии не
открывается.

`table_crc32` покрывает всё от конца заголовка до `pcm_offset` и
проверяется при старте. `pcm_crc32` пишет препроцессор, плата его **не
проверяет**: читать мегабайты через XIP на каждой загрузке слишком дорого.

Обе суммы — CRC-32 с отражённым полиномом `0xEDB88320` **без финальной
инверсии**. Проверочное значение на строке `123456789` — `0x340BC6D9`;
стандартный CRC-32 даёт его дополнение. Функция одна на обе стороны.

## Пресеты

Плоский массив на `банк * 128 + программа`. Банков 129: MIDI 0–127 плюс
синтетический 128 под ударные.

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 2 | `first_layer` — индекс в `layers` |
| 2 | 2 | число слоёв (биты 0–14) и флаг отката (бит 15) |

**Дырок нет.** Если такой вариации в исходном `.sf2` не было, препроцессор
подставил программу из банка 0, а не нашлось и её — рояль, и пометил слот
флагом отката. На плате логики подстановки нет: ответ всегда
корректен.

Число слоёв занимает 15 бит, а не байт: в рояле тяжёлых банков больше
тысячи зон.

## Слои

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 1 | `vel_lo` |
| 1 | 1 | `vel_hi` |
| 2 | 2 | `instrument` |

Слой звучит **одновременно** с другими слоями той же программы: это
наложение тембров, а не переключение по силе удара. В GeneralUser GS
слоисто 170 пресетов из 287. Конвертер поднимает по каналу на слой.

Диапазона нот здесь нет — он выражен keymap инструмента: вне диапазона
keymap отдаёт «нет сэмпла».

Индексные поля равны `0xFFFF`, когда записи нет.

`exclusive_class` перенесён, но движку не нужен: обрыв предыдущего звука
того же класса выписывает конвертер. Трекерные `DCT`/`DCA` тут не годятся —
они проверяют дубликаты внутри одного канала, а класс действует по всему
каналу MIDI, и слои одной ноты лежат на разных каналах.

## Огибающие

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 1 | `flags` |
| 1 | 1 | `point_count` — до 25 |
| 2 | 1 | `sustain_point` |
| 3 | 1 | `sustain_end` |
| 4 | 1 | `loop_start` |
| 5 | 1 | `loop_end` |
| 6 | 2 | запас |
| 8 | 100 | 25 точек по 4 байта: `ms` (2), `value` (2, знаковое) |

Флаги: `0x01` включена, `0x02` есть sustain, `0x04` есть петля, `0x08`
перенос состояния.

Время — **в миллисекундах, а не в тиках**: частота тиков
зависит от темпа конкретного файла, сетку под темп подбирает конвертер.
Огибающая в тиках означала бы отдельный банк под каждый темп. Конвертер
переводит при загрузке: `тик = мс × частота_тиков / 1000`.

## Keymap

| Смещение | Размер | Поле |
|---:|---:|---|
| 0 | 1 | `start_note` — первая нота диапазона включительно |
| 1 | 1 | `note_offset` — знаковый, читать как `int8` |
| 2 | 2 | `sample_index` — `0xFFFF` значит «нет сэмпла» |

Диапазоны идут подряд; конец одного — начало следующего.

`note_offset` выражает и обычное транспонирование, и `scaleTuning = 0`
(высота не зависит от клавиши): такая зона раскладывается в диапазоны по
одной ноте, у каждой свой сдвиг.

В `c5_speed` сведены корневая нота, грубая и точная подстройки и поправка
самого сэмпла — на плате пересчитывать нечего.

`global_volume` может быть **усилением**: `initialAttenuation` в SF2 бывает
отрицательным. В GeneralUser GS таких 98 зон из 21650, до +7 дБ, и почти
все — тарелки.

## Область PCM

Прогоны уложены ровно так, как их формирует упаковщик сэмплов движка:
тело, добивка до границы, следом контрольные точки. Загрузка сводится к
«выделить цепочку страниц PSRAM и распаковать прогон в неё подряд» — без
разбора и без перекодирования.

Сжатий здесь **два, и они разные по смыслу**:

| | Что | С потерями | Когда разжимается |
|---|---|---|---|
| Кодек сэмпла | 16 бит → байт на отсчёт | да | никогда: в PSRAM лежит так же |
| Сжатие банка | байты → поток ANS | нет | при загрузке сэмпла в PSRAM |

Первое определяет, **сколько сэмпл занимает в памяти платы**, второе —
**сколько он занимает в файле**.

## Кодек сэмпла: Dpcm8

Резидентный формат — байт на отсчёт, потому что в PSRAM иначе не помещается
библиотека. Простая линейная дельта ±127 на резких фронтах упирается в
потолок и даёт лесенку, поэтому шаг здесь плавающий.

Байт кода:

```
биты 7:5   масштаб, индекс таблицы {1, 3, 9, 27, 81, 243, 729, 2048}
биты 4:0   значение со знаком, −16..15

отсчёт += значение * масштаб[индекс]
```

Прогрессия примерно втрое. Верхний масштаб 2048, а не 2187 — иначе
`−16 × 2187` переполнило бы `int16`; при 2048 крайние значения дают ровно
−32768 и 30720.

Малые дельты передаются точно до единицы, большие — грубее, но без
обрезания фронта. Кодировщик после каждого байта прогоняет свой же декодер,
так что расхождения кодера и декодера быть не может по построению.

Состояние декодера — одно число, текущий отсчёт. Оно же **контрольная
точка**: каждые 256 отсчётов оно сохраняется, и с любой из них можно
начать декодирование, не проходя прогон с начала. Контрольные точки лежат в
том же прогоне, сразу за телом, и в `pcm_bytes` уже учтены.

Кроме Dpcm8 бывают `Raw8` (байт как есть) и `Raw16`. Выбирает препроцессор
**по измеренной ошибке кодирования**: кодирует, декодирует обратно, считает
отношение сигнал-шум и берёт лучший вариант, а не решает по формальному
признаку.

## Сжатие банка: tANS

Поверх кодека каждый прогон сжимается **без потерь**, табличным ANS. Это и
есть разница между `pcm_packed_bytes` и `pcm_bytes` в записи сэмпла; флаг
`0x02` говорит, что прогон сжат.

Модель — частоты символов, таблица `model` размером 2 КБ:

```
4 контекста × 256 символов × 2 байта = 2048
```

Контекст — **два старших бита предыдущего байта**. В байте Dpcm8 старшие
три бита это масштаб, а у звуковой волны соседние отсчёты меняются плавно,
и масштаб почти не скачет: предыдущий байт хорошо предсказывает следующий,
и энтропия падает заметно.

На плате в банке лежат только частоты; таблица распаковки строится из них
при загрузке трека, в резидентную арену. Распаковка одного байта — одна
выборка из этой таблицы: символ, сколько бит дочитать и база следующего
состояния. Из флеша это 9.9 МБ/с — быстрее, чем читается сама карта.
